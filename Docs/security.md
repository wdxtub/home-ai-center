# 安全模型

本文说清三件事：**谁在什么网络位置能做什么**、**哪些数据会被存下来**、**部署前要改哪几处**。
每条论断都指到源码位置；没写「以源码为准」的地方都可以直接核对。

**一句话结论**：这是一个**假定自己跑在可信家庭网络内**的网关。它默认监听
`0.0.0.0:8080`、只讲明文 HTTP、两套凭证互不通用。它防的是「家里人乱用、花超了、
互相踩队列」，**不防**「同一个局域网里的攻击者嗅探或直接打管理面」。

---

## 一、两套凭证模型

两套凭证**完全独立**，作用域、生命周期、存储方式都不同（`api/auth.rs`、
`api/admin.rs`、`migrations/0001_init.sql`、`migrations/0006_api_key_split.sql`）。

| | 管理台口令 | 调用方 API Key |
| --- | --- | --- |
| 载体 | 登录换取会话 token | 请求头直接带 |
| 头部 | Cookie `hac_session`（或 `x-admin-token`） | `Authorization: Bearer` / `x-api-key` |
| 作用域 | `/api/admin/*` 全部管理动作 | `/v1/*` 网关面 |
| 初始来源 | `HOME_AI_ADMIN_TOKEN`，**仅首次启动** | 管理台创建时现场生成 |
| 存储 | Argon2 哈希（`auth.rs:200`） | SHA-256 十六进制（`auth.rs:19`） |
| 校验频率 | 低频（登录） | **每请求一次** |
| 轮换 | 改口令 → 作废**所有**会话 | `/api-keys/{id}/rotate` → 只废这一把 |

### 为什么必须独立

管理面能看能改的东西远多于网关面：节点地址、**上游明文密钥**、定价、余额、备份。
一旦两者通用，拿到一把给手机用的调用 key 就等于拿到整个网关的控制权。
所以 `auth.rs` 里是两条互不相干的代码路径，凭证类型也不能互换提交。

### 明文只出现一次

调用方 key 由 `generate_api_key()`（`auth.rs:30`）现场生成，形如
`sk-hac-` + 40 位字母数字，**明文只在创建/轮换的那一个 HTTP 响应里出现一次**
（`admin.rs:312`、`admin.rs:489`、`admin.rs:558`）。落库的是
`hash_key(raw)` 和 `key_prefix(raw)`（前 8 个字符，`admin.rs:408-445`），
之后任何列表接口都只回 `key_prefix`（`admin.rs:373-387`）。

注意这里的 SHA-256 是**刻意**选的，源码写了原因（`auth.rs:6-7`）：每请求都要验一次，
Argon2 的参数就是选来慢的。因此它的防线是「库被读走也无法直接冒用」，
**不是**「能扛离线爆破」——SHA-256 无盐无轮次。

### 管理员口令的初始化只有一次

`ensure_admin()`（`auth.rs:228`）只在 `admin_user` 为空时插入，用户名**固定 `admin`**
（`0001_init.sql:220` 的 `CHECK (id = 1)` 加代码里的字面量）。之后
`HOME_AI_ADMIN_TOKEN` **完全不再影响**已存口令——即使 `admin_user` 已有行也直接 return。
忘了设这个变量只会看到一条 warn，管理台从此锁死，必须删库重来。

口令策略很松：只查 8～256 个字符（`domain/validate.rs:203-209`），不要求复杂度。
登录失败时先跑完 Argon2 校验再返回统一文案，避免用响应时间探测用户名
（`admin.rs:92-97`）。

会话与登录的其余性质：

- 会话 token 是 24 字节随机（48 个十六进制字符，`auth.rs:219`），有效期 7 天
  （`admin.rs:101`），Cookie 带 `HttpOnly; SameSite=Strict`。
- 走 HTTPS 时（直连，或反代透传 `X-Forwarded-Proto: https`）Cookie 追加 `Secure`
  （`admin.rs:50`、`admin.rs:109-115`）。**明文直连时故意不加**——加了浏览器
  根本不会在 http 上发，会话直接登不上。
- 改口令会 `DELETE FROM session` 清空全部会话。
- **登出会真的删掉库里的那一行**（`admin.rs:134`）。这一点曾经是错的：
  守卫验完 token 之后并没有把它传下来，登出执行的是 `DELETE … WHERE token = ''`，
  一行都没删到，而浏览器 Cookie 已经清了——「已登出」的凭证还能用满 7 天。
- **登录失败有节流**（`auth.rs:279` 的 `LoginThrottle`）：同一来源连续失败 5 次
  开始退让 60 秒，随失败次数翻倍，**上限 5 分钟**，登录成功即清零。
  只按对端 IP 计数，**不采信 `x-forwarded-for`**（那个头谁都能填，
  采信它等于节流可以被一个请求头绕开）。代价是网关在反代后面时
  所有登录算同一个来源——单管理员的家庭网关里这恰好是想要的。
  取不到对端地址时退化成单一来源，宁可一起限流也不完全不限流。

## 二、威胁模型与信任边界

### 三个面

路由实现在 `main.rs:200-217`：

- **网关面 `/v1/*`** — 调用方 API Key 鉴权（`auth.rs:132` 的 `Authed`）。
  能花账号的钱、调上游模型、**看到自己的余额与用量**。看不到别人的 key、看不到配置。
- **管理面 `/api/admin/*`** — 会话鉴权，守卫是挂在整个 Router 上的
  `require_admin` 中间件（`main.rs:193-196`、`main.rs:295`）；`/auth/login` 因为拆在
  `admin_public` 里而豁免。**能读上游明文密钥**（`admin.rs:956-967` 收明文写入，
  但列表只回 `mask()` 后的 `masked` 字段，`admin.rs:885-929`），
  能充值、能看到出图提示词。
- **`/api/health`** — **免鉴权**（`main.rs:203`、`main.rs:307`）。只回 `ok`、
  版本号、uptime、节点/模型**数量**和前端是否已编译。没有任何配置内容，
  但它让任何人能确认「这台机器上有个网关」。

### 错误响应不外泄后端拓扑

`reqwest` 的传输错误 `Display` 会把**完整请求 URL** 拼进去
（`error sending request for url (http://<内网地址>:8188/prompt)`），
上游 401 还经常把「你发来的 key」原样回显。网关把这两类字符串往上传，
就会让**任何持有调用方 key 的人**看到内网地址、端口、路径。

因此凡是回给客户端的上游错误都先过一遍 `upstream::sanitize`：

- URL 整段换成 `<upstream>`；
- `sk-…` / `Bearer …` / `api_key=…` 后面的凭证换成 `***`；
- 超过 200 字符截断（上游错误页可能好几 KB）。

保留的是**能据以行动的部分**：HTTP 状态码、错误类别、超时与否、上游自己说的原因。
**原文不丢**——三个失败分支都补了 `tracing::warn!`（`v1.rs:509-548`），
排障照旧。ComfyUI 的 `Workflow` 错误**故意不过滤**：它说的是「你提交的工作流哪里不对」，
调用方没有它就没法改，里面也没有网关的拓扑信息。

同理，限额错误里**不再带上游 key 的 label**（`v1.rs:498-501`），
节点名与地址也不出现在「节点不可达」里（`v1.rs:540-548`）——调用方据此决定
「等」还是「改路由」就够。

### 跨域默认关闭

CORS **默认不加任何层，即只允许同源**（`main.rs:222` 的 `build_cors`，
`HOME_AI_CORS_ORIGINS` 为空时返回 `None`）。内置前端是同源的（走 fallback），
开发时 vite 也代理到本机，所以默认关掉不影响正常使用。

需要跨源时用 `HOME_AI_CORS_ORIGINS` 显式列出允许的源，且**只放行真正用到的
请求头**（`Authorization` / `content-type` / `x-api-key` / `x-admin-token` /
`anthropic-version`），不是 `Any`。

**配错的源会告警，不会静默吞掉**（`main.rs:271` 的 `split_cors_origins`）：
必须带 `http://` / `https://` scheme，结尾不能有斜杠。少写 `https://` 是最常见的
错法，而且它**不会**被 `HeaderValue::from_str` 拦下——裸主机名是个合法的 header
值，于是「配了」却永远匹配不上浏览器发来的 `Origin`。这种项会单独挑出来打 warn。
静默丢掉拼错的 origin 属于「配了不生效」，比直接报错更难查。

### 网络位置决定一切

默认 `HOME_AI_BIND=0.0.0.0:8080`（`config.rs:59`），HTTP 无 TLS（`main.rs` 里没有
任何 TLS 配置，README「不做的事」明写 TLS 交给 Nginx/Caddy）。于是：

- **同一局域网内** — 任何设备都能连上。管理面靠口令守着，但**口令会在网络上明文传输**。
  这是当前部署形态下最大的实际风险。
- **公网可达时** — 不要。管理面等于敞开。

### 上游密钥 vs 调用方密钥

风险面完全不同，别混：

- **上游 key（`llm_node_key.secret`）** — **明文存库**（`0001_init.sql:60-64`，
  注释里写明是刻意的：假脱敏只会制造「key 对不上」的排障成本）。所以
  **`./data/home-ai-center.db` 文件泄露 = 上游额度直接被接管**。它只用于给上游
  发 `Authorization: Bearer`（`upstream/openai.rs:96`），不进日志。
- **调用方 key** — 库被读走也拿不到可用的凭证（只有 SHA-256 和 2 位有效前缀）。
  但反过来，**只要持有明文就能直接冒用**，没有任何二次验证。

## 三、数据留存与隐私

| 表 | 存什么 | 保留 |
| --- | --- | --- |
| `request_log` | **只有元数据**：谁、何时、调了哪个模型、多少 token、多少钱、耗时与首 token 等待 | 默认 90 天 |
| `usage_daily` | 日汇总 | **永久** |
| `image_prompt` | **出图提示词正文** | 跟随明细级联删除 |

**不记录 LLM 的 prompt / completion 正文**，这是产品决策（`0001_init.sql:158`
的建表注释、README「不做的事」）。`request_log` 只有 `prompt_tokens` /
`completion_tokens` 这类计数。取舍很清楚：正文是最占空间、也最敏感的部分，
而排查问题真正需要的「谁、何时、调了什么、多少钱」全在元数据里。

**唯一的例外是出图提示词**：`image_prompt` 独立成表（`0002_image_prompt_drop_archive.sql:1-20`），
理由是它是「这张图怎么来的」唯一可追溯线索，且很短。保留期不单独设开关——
`image_prompt.request_id` 上有 `ON DELETE CASCADE`（`0002:23`），
`purge_older_than` 删明细时提示词跟着走（`billing/usage.rs:346-353`），
不会变成一份永不过期的正文副本。默认 90 天来自
`DEFAULT_RETENTION_DAYS`（`tasks/retention.rs:14`），可在管理台改。

**数据目录里没有图片**：`ensure_dirs` 刻意不建 `images/`（`config.rs:88-95`），
出图以 base64 直接回给调用方。`error_message` 存的是**已经过脱敏的**错误文案
（净化规则见上文「错误响应不外泄后端拓扑」），原文只进日志。

**备份会把敏感数据一起带走**：`VACUUM INTO` 产出的 `.db` 是**整库快照**，
`./data/backups/` 里滚动 7 天（`admin.rs:1819`）。所以一份备份文件同时包含：
管理员口令哈希、会话 token、**上游明文密钥**、ComfyUI 明文口令
（`0001_init.sql:129-130`）、以及 90 天内的出图提示词。**备份文件按机密文件保管。**

## 四、加固清单

按优先级。前三条是「不照做就真的有风险」。

- [ ] **改掉默认口令。** `.env.example` 里是 `change-me-to-something-long`。
      首次启动后进「设置 → 管理员」改掉——之后改环境变量是**无效**的。
- [ ] **不要暴露到公网。** 只在可信局域网内访问。必须出网时，前面套
      Nginx / Caddy 做 TLS 终止并加访问控制（仓库明确不做 TLS 终止）。
- [ ] **收紧监听面。** 设 `HOME_AI_BIND=127.0.0.1:8080`（只本机）或
      `<内网地址>:8080`，不要留 `0.0.0.0`。需要跨设备时用防火墙规则限定来源网段。
- [ ] **保护 `./data` 目录。** 里面是整库 + 备份：`chmod 700 ./data`，
      只有运行网关的账号能读。备份另存到加密介质或加密备份系统。
- [ ] **每把 key 单独发。** 一台设备一把（`0006` 拆分就是为了这个），
      丢了一台只 `rotate` 那一把，不要动整账号。停用优先于删除——
      删除最后一把会被拒绝（`admin.rs:579-585`）。
- [ ] **定期轮换上游 key。** 上游 key 是明文存库的，轮换它同时降低
      「库泄露」的影响面。发现异常用量立刻在管理台停用对应 key。
- [ ] **缩短会话有效期。** 默认 7 天（`admin.rs:101`）偏长；共用设备上
      用完管理台就登出。登出现在会真的删掉 `session` 里的行
      （`admin.rs:134`），登出后再用同一把 token 会被 401。
- [ ] **别乱开 `HOME_AI_CORS_ORIGINS`。** 默认只允许同源，跨源必须显式列出
      允许的源，且每项都要带 `https://`。放开之后任意被列出的站点都能带着
      调用方 key 跨域打 `/v1` 并读响应。
- [ ] **套反代时确认 `X-Forwarded-Proto` 透传了。** 网关靠它决定要不要给
      会话 Cookie 加 `Secure`（`admin.rs:50`）。反代吞掉这个头，会话就永远
      少了 `Secure`——那正是套 TLS 的意义被架空的样子。

## 五、贡献者安全约定

这份文档本身是最后一道防线。开源仓库里最容易出事的是「顺手把真实配置贴进去」。

- [ ] `.env` 在 `.gitignore` 里（`.gitignore:5-6`），**从未进入过 git 历史**。
      可提交的是 `.env.example`，里面只有占位符。
- [ ] **绝不提交真实 token、口令、私有域名、真实内网 IP、真实机器名。**
      举例一律用占位符：`sk-hac-xxx`、口令 `change-me-to-something-long`、
      RFC1918 保留段 `192.168.1.20`、节点名 `<node-a>`。
- [ ] 新增示例、文档、测试数据时，先自问「这个值在真实部署里会出现吗」。
      会，就换成占位符。
- [ ] **日志里不打密钥、不打完整请求体。** 现有代码守住了这条：
      `api/*.rs` 里的 `tracing` 调用只打节点名、URL、request_id、错误类型
      （例如 `v1.rs:393`、`images.rs:174-180`），没有一处打请求体或凭证。
      `TraceLayer::new_for_http()`（`main.rs:207`）也不打请求头。
      **加日志时别破坏这个性质。**
- [ ] `scripts/import_erotic_sci.py` 的设计原则值得保持：**脚本里不含任何明文密钥**。
      上游 key 从源仓库的 `.env` / `ingest.yaml` 运行时读取
      （`import_erotic_sci.py:220-223`、`:295`），管理员口令读环境变量
      （`:552`），`--dry-run` 还会把 `_key` / `password` 打成 `***`（`:587-597`）。
      正因如此它可以安全提交。
- [ ] 提交前扫一遍：`git diff --cached | grep -iE 'sk-|token|password|192\.168\.|10\.'`，
      命中的逐条确认是不是占位符。

## 六、已知不做的事

安全上**明确不做**的，写下来是为了让部署者知道边界在哪：

- **不做 TLS 终止。** 默认 HTTP，套 Nginx / Caddy。会话 Cookie 的 `Secure`
  标记靠反代透传 `X-Forwarded-Proto: https` 决定。
- **不做分布式 / 多副本。** 单进程单库，调度状态在内存里。登录节流同样是
  进程内的：多副本部署会让限流按副本数打折。
- **不在网关留图片。** 图片由调用方保存，网关只回 base64。
- **只存调用方 key 的哈希，不存明文。** 反过来，**上游 key 和 ComfyUI 口令是明文存的**
  （`0001_init.sql:56-59` 有说明），这是已知的取舍，也是 `./data` 必须
  `chmod 700` 的直接原因。会话 token 同样明文存 `session` 表——所以
  备份文件要按机密保管。
- **不记录 LLM 正文。** 出图提示词是唯一例外。
- **不做 CSRF token。** 管理面靠 `SameSite=Strict` 防 CSRF。这是刻意的：
  跨域默认已关闭，需要跨源时靠 `HOME_AI_CORS_ORIGINS` 白名单放行。
- **不按 IP 之外的身份限流。** 没有账号级配额、没有多因子，口令 + 节流就是全部。
- **会话 token 不做服务端失效列表之外的加强**：改口令会清空全部会话
  （`admin.rs:200`），这是唯一的批量吊销手段。
